# CreateDocReturn2Supplier

Служебный Python-скрипт для автоматического создания документов возврата
поставщикам в базе AutoDealer. Проект получает заказы из Rossko и Profit-Liga,
сравнивает статусы товарных позиций с предыдущей ежедневной выгрузкой и передаёт
подходящие позиции в Firebird через внутреннюю библиотеку `autodealerAPI`.

> [!WARNING]
> `python main.py` создаёт документы в базе, указанной в параметре `db_path`.
> Параметр `db_path_test` в текущей реализации не используется. Перед первым
> рабочим запуском обязательно проверьте подключение и сделайте резервную копию
> базы данных.

## Как работает проект

При каждом запуске скрипт:

1. Запрашивает заказы за период от `вчера − 63 дня` до вчерашнего дня
   включительно.
2. Сохраняет исходные ответы API в `data/data_backup`.
3. Формирует для каждого поставщика сериализованный снимок `ProductList` в
   формате `pickle`.
4. Сравнивает новый снимок со снимком предыдущего дня.
5. Отбирает позиции, статус которых изменился на нужный для возврата:
   - Rossko — новый статус `31` или `36`, кроме перехода `31 → 36`;
   - Profit-Liga — новый статус `20`.
6. Создаёт и заполняет отдельный документ возврата для каждого поставщика в
   одной транзакции.

Используемые в коде идентификаторы контрагентов:

| Поставщик | ID контрагента |
|---|---:|
| Rossko | `8880` |
| Profit-Liga | `8876` |

Если снимка за предыдущий день ещё нет, поставщик пропускается. Поэтому первый
запуск используется для формирования исходного состояния и не создаёт по нему
документ возврата.

## Требования

- Windows — в проекте используются абсолютные Windows-пути и обратные слеши;
- Python `3.13.14` или совместимая версия согласно `pyproject.toml`;
- доступ к API Rossko и Profit-Liga;
- доступ к целевой базе Firebird;
- внутренний пакет `autodealerAPI` версии `0.1.7`;
- менеджер пакетов [uv](https://docs.astral.sh/uv/) — рекомендуемый способ
  установки зависимостей.

Пакет `autodealerAPI` подключён в `pyproject.toml` как локальный wheel:

```toml
[tool.uv.sources]
autodealer-api = { path = "../../ALL/autodealerAPI/dist/autodealer_api-0.1.7-py3-none-any.whl" }
```

Перед установкой убедитесь, что wheel существует по этому пути, либо замените
путь на актуальный для вашей машины.

## Установка

Из корня проекта выполните:

```powershell
uv sync
```

Файл `requirements.txt` также содержит локальную Windows-ссылку на
`autodealerAPI`, поэтому перенос проекта на другую машину требует обновления
этого пути.

## Конфигурация

Создайте в корне проекта файл `config.ini`. Он исключён из Git и должен иметь
следующую структуру:

```ini
[DEFAULT]
delta_days = <смещение в днях>
disputParts_fp = <путь к данным спорных позиций>

[Rossko]
URL = <URL WSDL Rossko>
first_secret = <первый ключ>
second_secret = <второй ключ>

[Profit]
URL = <URL API Profit-Liga>
key = <ключ API>

[Database]
db_path = <путь к рабочей базе Firebird>
db_path_test = <путь к тестовой базе>
db_user = <пользователь>
db_password = <пароль>
```

Не добавляйте `config.ini` в репозиторий: файл содержит ключи API и учётные
данные базы.

## Пути и рабочие каталоги

Запускайте проект из его корневого каталога: `config.ini`, `logs` и
`data/data_backup` открываются относительно текущей рабочей директории.

Перед развёртыванием проверьте абсолютные пути, зашитые в исходном коде:

| Назначение | Файл |
|---|---|
| ежедневные `pickle`-снимки | `back/get_data.py`, константа `TDATA_PATH` |
| журнал `dataobject.log` | `back/utilities/dataobject.py` |
| журнал фреймворка `frame.log` | `back/request_db.py` |

Каталоги для снимков, резервных JSON-файлов и журналов должны существовать и
быть доступны на запись пользователю, от имени которого запускается скрипт.

Имена ежедневных файлов строятся по дню недели, например
`Monday_rossko.pkl` и `Monday_profit.pkl`. Через неделю файл с тем же именем
перезаписывается. Исходные JSON-ответы сохраняются аналогичным образом в
`data/data_backup`.

## Запуск

После настройки окружения и путей:

```powershell
uv run python main.py
```

У скрипта нет аргументов командной строки. Для ежедневной автоматической работы
его можно запускать из Планировщика заданий Windows, задав корень проекта как
рабочий каталог.

Основные журналы:

| Файл | Содержимое |
|---|---|
| `logs/global.log` | запуск и ошибки верхнего уровня |
| `logs/get.log` | запросы к API и фильтрация позиций |
| `logs/req.log` | создание и заполнение документов |
| `logs/frame.log` | сообщения `autodealerAPI` |
| `logs/corrupt_data.log` | журнал для ошибок данных |

Непредвиденная ошибка получения данных или записи в БД завершает процесс с
кодом `1`. Отсутствие подходящих данных и обрабатываемые `AssertionError`
завершают его без ошибки.

## Тесты

Автоматические тесты написаны на стандартном `unittest`:

```powershell
uv run python -m unittest discover -s tests/autotests -p "test_*.py"
```

В `tests/handtests` находятся вспомогательные сценарии для ручной проверки и
анализа сохранённых данных. Они не входят в автоматический прогон и могут
использовать локальные файлы.

## Структура проекта

```text
.
├── main.py                         # точка входа
├── back/
│   ├── get_data.py                # сбор, сравнение и фильтрация данных
│   ├── request_db.py              # создание документов в Firebird
│   └── utilities/
│       ├── dataobject.py          # ProductList и работа с pickle
│       ├── rosskoNprofit.py       # клиенты API поставщиков
│       └── utils.py               # конфигурация, даты и логирование
├── data/
│   ├── data_backup/               # резервные ответы API в JSON
│   └── temp/                      # локальные временные данные
├── logs/                           # журналы работы
├── tests/
│   ├── autotests/                 # модульные тесты
│   └── handtests/                 # ручные проверки
├── config.ini                      # локальная конфигурация, не хранится в Git
├── pyproject.toml
└── uv.lock
```

## Известные ограничения текущей версии

- Перенос `utilities` внутрь `back` не завершён: часть импортов всё ещё ожидает
  пакет `utilities` в корне, а часть — файл `_utils.py`, хотя в рабочем дереве
  находится `back/utilities/utils.py`. До выравнивания импортов запуск и тесты
  могут завершаться с `ModuleNotFoundError`.
- Несколько путей привязаны к каталогу
  `C:\Program Files\_Scripts\Create_ReturnNomeclature`; для другого места
  установки их нужно изменить в исходном коде.
- Локальная зависимость `autodealerAPI` не публикуется из обычного реестра и
  должна быть доступна отдельно.
- `pickle`-файлы нельзя загружать из недоверенного источника.
